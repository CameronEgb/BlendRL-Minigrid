# Experiment and Plotting Guide

This document provides a human-readable guide to specifying experiments, managing configurations, running training pipelines, and generating visualizations in the BlendRL codebase.

---

## 1. Experiment Configurations (Hydra)

All experiments are structured using **Hydra**. Configurations are stored under the `conf/` directory:

```
conf/
├── config.yaml          # Base defaults, SLURM defaults, and paths
├── agent/               # Agent hyperparameters (ppo, iql, blendrl, cql, etc.)
├── env/                 # Environment-specific settings (cartpole, seaquest, etc.)
├── mode/                # Execution modes (online, offline)
├── experiment/          # Predefined global experiment setups (e.g., cp_final.yaml)
├── plot_styles/         # Plotting configurations (default, per_online)
└── plot_sources/        # Custom run collections for comparisons
```

### Precedence Rules
Hydra applies overrides in the following order:
$$\text{CLI overrides (e.g., ++agent.lr=0.005)} > \text{Experiment YAML} > \text{Defaults (config.yaml)}$$

### Creating a New Experiment Config
To create a new run configuration (e.g., `conf/experiment/cp_test.yaml`):
1. Add `# @package _global_` at the top. This exposes variables to the root config scope.
2. Override base presets in the `defaults` section.
3. Define custom parameters:

```yaml
# @package _global_
defaults:
  - override /env: cartpole      # Uses conf/env/cartpole.yaml presets
  - override /mode: online       # Defaults to online mode (can be changed in runs)

experiment_id: cp_test           # Key for logging folder
group: debug                     # High-level group folder
total_timesteps: 50000           # Number of online transitions to collect
intervals_count: 5               # Number of evaluation/checkpoint snapshot intervals
eval_episodes: 100               # Number of episodes for evaluation callback

online_methods: ppo/cp_tuned,blendrl/cp_tuned
offline_methods: iql/cp_tuned,blendrl_iql/cp_tuned
```

### Overriding Parameters from the CLI
You can override any variable at runtime. Always use `++` to override or add nested parameters:
```bash
# Override learning rate and seed on the fly
python run_pipeline.py cp_final ++agent.lr=0.001 ++seed=2
```

## 2. Pipeline Execution (`run_pipeline.py`)

The main entry point for running experiments is `run_pipeline.py`. It automates the execution of online methods, saving datasets, running offline methods on those datasets, and plotting the results.

### Command Format
```bash
python run_pipeline.py [experiment_name] [options] [hydra_overrides]
```

### Key CLI Options and Flags
| Flag | Action | Description |
| :--- | :--- | :--- |
| `--local` | True/False | Run standard subprocesses locally (default: `True`). Set `--local=false` for Slurm cluster submission. |
| `--no-plot` | Flag | Skip automatic plot generation at the end of the run. |
| `--no-online` | Flag | Skip online data-collection training (Phase 1). Will search for existing datasets. |
| `--no-offline` | Flag | Skip offline training (Phase 2). |
| `--plot-style` | Path/Name | Path or name of plot YAML under `conf/plot_styles/` (e.g. `per_online`). |
| `--no-dash` | Flag | Disable the automatic launching of the Optuna dashboard. |
| `--dash-only` | Flag | Launch the Optuna dashboard locally in a persistent mode and exit. |

### Running Hyperparameter Sweeps (Optuna)
To run a multirun sweep, pass the `-m` (or `--multirun`) flag along with parameter ranges:
```bash
python run_pipeline.py quick_test -m agent.lr="interval(1e-4, 1e-2)" agent.tau="interval(0.5, 0.9)"
```
*   This automatically fires up a local SQLite database (`optuna.db`) and launches the **Optuna Dashboard** in your browser at `http://127.0.0.1:8080` so you can monitor trial convergence in real time.

## 3. Plotting and Visualizations (`plot_results.py`)

Visualizations are generated by `plot_results.py`. It recursively reads CSV logs from `results/logs/` or pre-restructured `results.json` files.

### Command Format
```bash
python plot_results.py [experiment_name] [options]
```

### Key CLI Options and Flags
| Option / Flag | Description |
| :--- | :--- |
| `experiment` | Position argument. Experiment ID or comma-separated list of IDs to filter and plot. |
| `--show-versions` | Plots each historical run version (e.g., `v0`, `v1`, `v2`) as a separate color line instead of aggregating/averaging them together. Also generates `all_plots.png`. |
| `--style` | Path or name of style configuration YAML (stored under `conf/plot_styles/`). |
| `--sources` | Path or name of a YAML file specifying explicit run paths to plot together (stored under `conf/plot_sources/`). |

### Customizing Styles (`conf/plot_styles/`)
You can control titles, metric columns, smoothing windows, and axes via style YAML configs:
```yaml
plots:
  - metric: "eval/reward"
    title: "Evaluation Reward: {experiment}"
    filename: "eval_reward.png"
    ylabel: "Avg Reward"
    window: 1                   # Rolling average window size for smoothing
    x_axis: "transitions"       # 'transitions' or 'step' (training epochs/epochs)
```
To split runs into separate plot files based on their dataset source:
```yaml
  - metric: "eval/reward"
    split_by: "source"          # Creates one plot per offline dataset source
    title: "Reward on Source {split_value}: {experiment}"
    filename: "eval_reward_{split_value}.png"
```

### Specifying Comparative Runs (`conf/plot_sources/`)
If you want to compare arbitrary run folders across different experiments, seeds, or groups, create a YAML sources file:
```yaml
runs:
  - path: "results/logs/ungrouped/cp_final/ppo_cp_tuned"
    label: "PPO Base"
    version: [0, 1]              # Plots version_0 and version_1 of PPO side-by-side
  - path: "results/logs/ungrouped/cp_final/blendrl_cp_tuned"
    label: "BlendRL Optimized"
    version: 3                  # Plots version_3 only
```
Then run the plotter with:
```bash
python plot_results.py --sources conf/plot_sources/[sources_file].yaml
```

## 4. Local-to-Cluster Workflow

To save time and budget on cluster instances, apply this pipeline progression:

### Step 1: Local Sanity Check
Confirm that the methods run, evaluate, save transitions, and plot without crashing using minimal timesteps:
```bash
python run_pipeline.py cp_final total_timesteps=1000 intervals_count=2 eval_episodes=5 local=true save_dataset=false
```

### Step 2: Local Search / Optimization
Run multiruns locally with a low trial limit to check optimization trends:
```bash
python run_pipeline.py quick_test -m agent.lr="choice(3e-4,1e-3)" hydra.sweeper.n_trials=5
```

### Step 3: Cluster Deployment
Once validated, submit jobs to the Slurm scheduler:
```bash
# Deploys online and offline jobs to the cluster
python run_pipeline.py cp_final local=false
```
After the remote run completes, synchronize the `results/logs/` and `results/checkpoints/` directories back to your local machine for analysis and plotting.
